# LLM ETL — инструкция по пользованию

Система на кассе **viki-BOX** принимает файлы выгрузки (1С EnterpriseData, CommerceML 2.05
и др.), разбирает их встроенными парсерами и пишет в базу SQLite (42 таблицы розничной схемы).
Если формат **незнакомый** — файл попадает в карантин, и система сама учится его читать
(см. раздел «Автообучение»).

---

## 1. Как открыть интерфейс

Касса слушает на двух портах (доступ — с устройства в той же сети, что и касса,
LAN-адрес кассы `192.168.243.136`):

| Что | Адрес | Назначение |
|-----|-------|-----------|
| **Веб-интерфейс** | `http://192.168.243.136:8081/` | страницы для человека (статус, загрузка, БД) |
| **API** | `http://192.168.243.136:8080/` | программный приём файлов (curl / интеграции) |

> Если открываете прямо на кассе — адрес `http://127.0.0.1:8081/`.

Разделы веб-интерфейса (меню сверху):
- **📊 Статус** — сводка: сколько записей в БД, какие парсеры активны, работает ли нейросеть.
- **⬆ Загрузить файл** — выбор и отправка файла на разбор (см. ниже).
- **📦 База данных** — список таблиц, просмотр строк, выгрузка CSV.
- **📁 Форматы** — какие форматы известны, какие на обучении, какие в карантине.

---

## 2. Загрузить файл через веб (выбор файла мышкой)

1. Откройте **`http://192.168.243.136:8081/upload`** (или меню → «⬆ Загрузить файл»).
2. Нажмите кнопку выбора файла, укажите XML/CSV-выгрузку.
3. Нажмите **«Разобрать и записать в БД»**.
4. Откроется страница **«Результат разбора»**:
   - каким **парсером** разобран (зелёный бейдж = известный формат; оранжевый
     «нейросеть» = новый формат, ушёл на обучение);
   - сколько записей извлечено и **вставлено в БД** (по таблицам);
   - ошибки записи, если были.

**Важно про скорость:**
- известный формат (1С / CommerceML) — разбирается **мгновенно** (миллисекунды);
- **незнакомый** формат поднимет нейросеть на CPU кассы — это **долго (~10–15 минут
  на файл)**, страница будет «думать». Это нормально и происходит только для новых форматов.

---

## 3. Загрузить файл без браузера (curl / интеграция)

```bash
# multipart-форма (как из браузера):
curl -X POST -F "file=@/путь/выгрузка.xml" http://192.168.243.136:8080/ingest

# сырое тело + имя файла в заголовке:
curl -X POST --data-binary @/путь/выгрузка.xml \
     -H "X-Filename: выгрузка.xml" \
     http://192.168.243.136:8080/ingest/raw
```
Ответ — JSON: `parser`, `records` (извлечённые записи), `db` (вставлено/пропущено/ошибки),
`quarantined` (true, если формат пока незнаком).

## 4. Посмотреть результат

- **Веб → 📦 База данных**: клик по таблице (`catalog_product`, `variant_barcode`,
  `doc_accept_invoice` и т.д.), кнопка **«⬇ скачать CSV»** для выгрузки.
- **API**: `GET http://192.168.243.136:8080/status` — счётчики строк по всем таблицам.

## 5. Автообучение парсеров (как система осваивает новый формат)

Это происходит **само, на кассе**, нейросеть в оперативной работе не участвует:

1. Пришёл файл неизвестной структуры → встроенные парсеры не узнали → **карантин**
   (группируется по «отпечатку» структуры).
2. Набралось **≥ 5 примеров** одного формата → нейросеть **размечает** их (разово, офлайн).
3. Из разметки генерируется **YAML-парсер** этого формата.
4. Парсер проходит **теневую проверку** (точность F1 на примерах); при F1 ≥ 0.85 —
   **повышается в рабочие**.
5. Дальше файлы этого формата читаются **детерминированно за миллисекунды**, нейросеть
   больше не нужна. В разделе **📁 Форматы** статус меняется: 🟡 собирает → 🧪 тестируется → ✅ работает.

## 6. Сервисы и доступ (для администратора)

На кассе (`ssh kassa`, root):
```bash
systemctl status llm-etl-api      # API приёма файлов (:8080), всегда включён
systemctl status llm-etl-viewer   # веб-интерфейс (:8081), всегда включён
systemctl status llm-etl-llm      # нейросеть (:8180), поднимается по требованию, гаснет через 60с простоя
journalctl -u llm-etl-api -f      # логи API (логи пишутся в RAM, не на eMMC)
```
Корень установки: `/opt/llm-etl/` · база: `/opt/llm-etl/data/etl.db` ·
модель: `/opt/llm-etl/models/active.gguf`.

## 7. Ограничения и предостережения

- **Нейросеть на CPU кассы медленная** (~1.3 ток/с генерация) — разметка нового формата
  занимает минуты. Это разовая цена за формат; рабочий разбор потом мгновенный.
- **0.5B-модель размечает неконсистентно** (имена/штрихкоды/артикулы — верно; внутренние
  id и группы товаров — нестабильно). Для высокой точности по группам/типам — модель 1.5B.
- **eMMC кассы изношен** — не гонять на устройстве лишних записей; логи уже переведены в RAM.
  При физическом доступе проверить: `e2fsck -f /dev/mmcblk0p6` и здоровье флеш-памяти.

  LLM ETL — КОНФИГУРАТОР ПАРСЕРА ДАННЫХ
  Инструкция для пользователя (не программиста)
════════════════════════════════════════════════════════════════════════════

ЧТО ЭТО
────────────────────────────────────────────────────────────────────────────
Программа берёт «сырые» файлы (выгрузки 1С, чеки ОФД, накладные ЭДО,
прайсы поставщиков, EDI-форматы) и через локальную нейросеть раскладывает
их по таблицам базы данных.

Внутри — небольшая нейросеть, обученная конкретно под вашу схему БД и под
форматы, которые вы ей покажете. Никаких облаков, всё на ваших устройствах.


────────────────────────────────────────────────────────────────────────────
ТРИ МАШИНЫ В СИСТЕМЕ
────────────────────────────────────────────────────────────────────────────

1) ЭТОТ КОМПЬЮТЕР  (Windows)
   Роль: РАБОЧЕЕ МЕСТО.
   - Здесь вы пишете обучающие примеры через веб-интерфейс.
   - Здесь же редактируется код и собираются архивы для других машин.
   - Нейросеть тут НЕ запускается. Никакой нагрузки на CPU/RAM.

2) GPU-МАШИНА  (Linux Ubuntu 24.04, NVIDIA RTX 5090)
   Роль: ЛАБОРАТОРИЯ.
   - Сюда вы привозите ваши обучающие примеры.
   - Здесь скачивается базовая нейросеть (Qwen2.5-Coder-1.5B).
   - Здесь же она дообучается на ваших примерах.
   - На выходе — один файл .gguf размером ~1 ГБ.

3) ЦЕЛЕВОЕ УСТРОЙСТВО  (Linux Debian 11 ARM, RK3566, 4 ГБ RAM, 32 ГБ диск)
   Роль: PRODUCTION (продакшн).
   - Сюда привозится готовый .gguf файл.
   - Здесь работает движок llama.cpp как системный сервис.
   - Принимает HTTP-запросы по порту 8080 и парсит файлы.


────────────────────────────────────────────────────────────────────────────
ЦИКЛ РАБОТЫ
────────────────────────────────────────────────────────────────────────────

  ① разметка примеров           → ② обучение на GPU       → ③ продакшн
  (этот компьютер)                 (Ubuntu + 5090)           (Debian ARM)
                                                                  ↑
                                                                  │
                                                              работает!
                                                              парсит файлы
                                                              по HTTP

  Если на ③ модель ошибается на каком-то новом формате — добавляете
  ещё примеров на ①, повторяете ② и ③. Старые знания не теряются
  (replay-buffer 20%).


════════════════════════════════════════════════════════════════════════════
  ШАГ 0.  ПЕРВИЧНАЯ УСТАНОВКА НА РАБОЧЕМ КОМПЬЮТЕРЕ (один раз)
════════════════════════════════════════════════════════════════════════════

  Откройте папку C:\projects\llm_etl\

  Правый клик на «ПЕРВЫЙ_ЗАПУСК.bat» → «Запуск от имени администратора»

  Поставится только лёгкий набор Python-библиотек (gradio, sqlalchemy и т.п.).
  НИКАКОЙ нейросети тут НЕ ставится — машина не нагружается.


════════════════════════════════════════════════════════════════════════════
  ШАГ 1.  ЕЖЕДНЕВНАЯ РАБОТА — РАЗМЕТКА ПРИМЕРОВ
════════════════════════════════════════════════════════════════════════════

  Двойной клик на «ЗАПУСК.bat» — откроется браузер на http://localhost:7860

  Вкладка «📝 Обучающие примеры»:
    1. Слева вставьте кусок данных (например, фрагмент выгрузки 1С).
    2. Справа НАПИШИТЕ JSON-ответ — как ДОЛЖНА была бы разобрать модель.
    3. Нажмите «💾 Сохранить пример».

  ВНИМАНИЕ: пока модель не обучена, кнопка «🤖 Авторазметка» не работает
  (потому что на этой машине нет нейросети). После того как модель будет
  готова на target-устройстве и вы подключите её через настройки —
  авторазметка заработает (UI будет ходить за ответом на target по HTTP).

  Когда наберётся 20-50 примеров — переходите к шагу 2.


════════════════════════════════════════════════════════════════════════════
  ШАГ 2.  УПАКОВКА И ПЕРЕНОС НА GPU-МАШИНУ
════════════════════════════════════════════════════════════════════════════

  Двойной клик: «УПАКОВАТЬ_ДЛЯ_ОБУЧЕНИЯ.bat»
  → Получите файл llm_etl_for_training.zip (~100 КБ, без моделей)

  Скопируйте этот ZIP на GPU-машину (Ubuntu) любым способом:
  scp, USB-флешка, общая папка, RDP/SSH/AnyDesk и т.д.

  Внутри ZIP лежат скрипты на bash (.sh) — они для Ubuntu, не для Windows.


════════════════════════════════════════════════════════════════════════════
  ШАГ 3.  ОБУЧЕНИЕ НА GPU-МАШИНЕ (Ubuntu 24.04 + RTX 5090)
════════════════════════════════════════════════════════════════════════════

  Распакуйте архив, например в /home/user/llm_etl/

  Откройте терминал в этой папке. Выполните по очереди:

      chmod +x gpu_host/*.sh
      sudo ./gpu_host/1_install.sh

  Установится: PyTorch с CUDA 12.4, HuggingFace стек, llama.cpp.
  Это разово. Занимает 15-30 минут.

  Затем:

      ./gpu_host/2_train.sh

  Скачается базовая модель Qwen2.5-Coder-1.5B (~3 ГБ, один раз) и
  запустится обучение. На вашей 5090 это займёт примерно 20-60 минут
  в зависимости от количества примеров.

  Затем:

      ./gpu_host/3_export_gguf.sh

  Получится файл:
      dist/etl-parser-q4_k_m.gguf      ← ~1 ГБ, готов для target

  Скопируйте этот один файл на целевое устройство (см. шаг 4).


════════════════════════════════════════════════════════════════════════════
  ШАГ 4.  УСТАНОВКА НА ЦЕЛЕВОЕ УСТРОЙСТВО (Debian 11 ARM, RK3566)
════════════════════════════════════════════════════════════════════════════

  ШАГ 4а. Первичная установка (один раз)

      На устройстве откройте терминал по SSH:

          sudo bash target_host/target_install.sh

      Установится: build-essential, cmake, llama.cpp скомпилируется
      под ARM64 с NEON-оптимизацией. Создастся systemd-сервис llm-etl.

      Занимает 20-40 минут (компиляция llama.cpp на RK3566 не быстрая).

  ШАГ 4б. Загрузка обученной модели (каждый раз после нового обучения)

      Скопируйте файл etl-parser-q4_k_m.gguf на устройство (scp/sftp).
      Затем на устройстве:

          sudo bash target_host/target_deploy_model.sh \
              /home/user/etl-parser-q4_k_m.gguf

      Скрипт:
        - проверит свободное место
        - перенесёт модель в /opt/llm-etl/models/
        - переключит активный симлинк
        - перезапустит сервис
        - сделает health-check

      Старые версии моделей сохраняются (последние 3) — можно откатиться.

  ШАГ 4в. Проверка состояния

          bash target_host/target_status.sh

      Покажет: статус сервиса, какая модель активна, отвечает ли HTTP,
      сколько RAM и диска занято.


════════════════════════════════════════════════════════════════════════════
  ШАГ 5.  ИСПОЛЬЗОВАНИЕ ИЗ ПРОДАКШНА
════════════════════════════════════════════════════════════════════════════

  Когда модель работает на target-устройстве, на него можно посылать
  данные по HTTP с любой машины в той же сети:

      curl -X POST http://<IP-устройства>:8080/v1/chat/completions \
           -H "Content-Type: application/json" \
           -d @ваш-файл-запроса.json

  Из веб-интерфейса на рабочем компьютере: откройте «⚙ Настройки»,
  в config/model.yaml укажите:
      inference_backend: "llama_server"
      llama_server:
        url: "http://<IP-устройства>:8080"

  Перезапустите ЗАПУСК.bat — теперь вкладка «🔍 Разбор данных» и
  кнопка «🤖 Авторазметка» работают через эту удалённую нейросеть.


════════════════════════════════════════════════════════════════════════════
  ДООБУЧЕНИЕ — НОВЫЕ ФОРМАТЫ ПОЯВИЛИСЬ
════════════════════════════════════════════════════════════════════════════

  1) На рабочем компьютере добавьте 5-20 новых примеров через UI.
  2) «УПАКОВАТЬ_ДЛЯ_ОБУЧЕНИЯ.bat» — соберёт ВСЕ примеры (старые + новые).
  3) На GPU-машине: ./gpu_host/2_train.sh + ./gpu_host/3_export_gguf.sh
  4) На target: target_deploy_model.sh с новым .gguf
  5) Сервис автоматически перезапустится с новой моделью.

  Старые знания не теряются: в обучение подмешиваются 20% старых примеров.


════════════════════════════════════════════════════════════════════════════
  ВАЖНЫЕ ФАЙЛЫ И ПАПКИ
════════════════════════════════════════════════════════════════════════════

  На рабочем компьютере:
    C:\projects\llm_etl\
    ├── ЗАПУСК.bat                       ← открыть UI
    ├── ПЕРВЫЙ_ЗАПУСК.bat                ← установка (один раз)
    ├── УПАКОВАТЬ_ДЛЯ_ОБУЧЕНИЯ.bat       ← собрать ZIP для GPU
    ├── examples/training_data/          ← ваши .jsonl примеры
    ├── config/
    │   ├── schema.sql                   ← структура БД (40+ таблиц)
    │   ├── model.yaml                   ← какая модель используется
    │   └── training.yaml                ← параметры обучения
    ├── gpu_host/                        ← .sh скрипты для Ubuntu
    │   ├── 1_install.sh
    │   ├── 2_train.sh
    │   └── 3_export_gguf.sh
    └── target_host/                     ← .sh скрипты для Debian ARM
        ├── target_install.sh
        ├── target_deploy_model.sh
        └── target_status.sh

    /home/user/llm_etl/

    ├── llama.cpp/                       ← движок (скомпилирован)
    ├── models/etl_lora_adapter/         ← LoRA адаптер
    └── dist/etl-parser-q4_k_m.gguf      ← готовая модель для target

    /opt/llm-etl/
    ├── llama-server                     ← бинарник
    ├── models/
    │   ├── active.gguf                  ← симлинк на текущую модель
    │   └── etl-parser-20260521-*.gguf   ← версии моделей
    /etc/systemd/system/llm-etl.service  ← systemd-юнит


════════════════════════════════════════════════════════════════════════════
  ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
════════════════════════════════════════════════════════════════════════════

  На рабочем компьютере не открывается браузер
    → http://localhost:7860 ввести вручную

  На GPU-машине обучение падает «CUDA out of memory»
    → В config/training.yaml уменьшить per_device_train_batch_size
      с 8 до 4 или 2

  На target-устройстве сервис llm-etl не стартует
    → bash target_host/target_status.sh
    → sudo journalctl -u llm-etl.service -n 50

  На target-устройстве недостаточно памяти
    → Модель должна быть Q4_K_M (~1 ГБ). Если ставили Q8 или f16 —
      нужна другая квантизация. На GPU-машине запустите export
      с другими параметрами.

  LLM ETL — установка на ARM-устройство
═══════════════════════════════════════════════════════════════════════════

ЧТО ЭТО
────────────────────────────────────────────────────────────────────────────
Программа принимает файлы (выгрузки 1С, прайсы, чеки) по HTTP, разбирает их
и кладёт в локальную SQLite-БД. Работает полностью автономно — интернет
нужен ТОЛЬКО ОДИН РАЗ для установки системных пакетов (apt install).

РЕСУРСЫ
────────────────────────────────────────────────────────────────────────────
  Диск:  ~1.2 ГБ (модель + бинарник llama.cpp + код)
  RAM:   ~250 МБ в режиме ожидания
  RAM:   ~1.7 ГБ во время разбора неизвестных файлов (LLM загружается)

УСТАНОВКА
────────────────────────────────────────────────────────────────────────────
1. Скопируйте этот архив (~1 ГБ) на устройство любым способом —
   флешка, scp, sftp, USB-диск.

2. На устройстве (Debian 11/12 или Ubuntu 22.04/24.04 ARM64):

       tar -xzf llm-etl-arm-*.tar.gz
       cd llm-etl-arm-*
       sudo bash arm_install.sh

3. Скрипт сам:
   - установит системные пакеты
   - создаст служебного пользователя
   - скомпилирует llama.cpp под ARM (10-30 минут на RK3566)
   - запустит сервисы

4. После окончания установки — откройте в браузере веб-интерфейс:

       http://<IP-устройства>:8081

   Там вы увидите статус системы, базу данных и список форматов.

КАК ПОЛЬЗОВАТЬСЯ
────────────────────────────────────────────────────────────────────────────

ОТПРАВИТЬ ФАЙЛ НА РАЗБОР:

   curl -X POST -F file=@my_export.xml http://<IP-устройства>:8080/ingest

В ответ придёт JSON со списком разобранных записей и именем парсера,
который сработал (или "LLM" если был задействован парсер нейросетью).

ПРОВЕРИТЬ СОСТОЯНИЕ:

   curl http://<IP-устройства>:8080/status

ПОСМОТРЕТЬ БАЗУ:

   Откройте в браузере http://<IP-устройства>:8081/db

ПОСМОТРЕТЬ ФОРМАТЫ:

   http://<IP-устройства>:8081/formats

ЕСЛИ ЧТО-ТО НЕ ТАК
────────────────────────────────────────────────────────────────────────────

Сервисы не запускаются:
    sudo journalctl -u llm-etl-api -n 50
    sudo journalctl -u llm-etl-viewer -n 50

Перезапустить:
    sudo systemctl restart llm-etl-api llm-etl-viewer

Остановить полностью:
    sudo systemctl stop llm-etl.target

Запустить нейросеть вручную (для отладки):
    sudo systemctl start llm-etl-llm

Удалить всё:
    sudo systemctl stop llm-etl.target
    sudo systemctl disable llm-etl-api llm-etl-viewer
    sudo rm -rf /opt/llm-etl /etc/systemd/system/llm-etl-*
    sudo userdel llm-etl
    sudo systemctl daemon-reload

ЧТО ДЕЛАЕТ СИСТЕМА КОГДА ВИДИТ НОВЫЙ ФОРМАТ
────────────────────────────────────────────────────────────────────────────

Первые 5 раз — обрабатывает медленно через нейросеть (~15-30 секунд),
параллельно сохраняет образцы файла.

После 5-го файла одного типа — нейросеть автоматически создаёт новый
парсер. Парсер тестируется в "тихом режиме" на следующих 20 файлах.

Когда точность парсера ≥ 95% — он автоматически становится активным,
и нейросеть больше не нужна для этого формата. Время обработки одного
такого файла становится около 5 мс.

Нейросеть выключается через 1 минуту простоя — освобождает ~1.5 ГБ RAM.
